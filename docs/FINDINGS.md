# Что выяснилось в процессе

Всё ниже — результат многочасовой отладки на живой станции. Если вы застряли на одном из
этапов, скорее всего ответ здесь.

## 1. Почему MITM перестаёт работать через пару минут

Классическая картина при попытке включить ADB через подмену `quasar.yandex.net`:

- сразу после сброса станция **принимает** поддельный сертификат и забирает конфиг;
- через 1–3 минуты — `SSL_do_handshake() failed ... tlsv1 alert unknown ca`.

Причина не в прошивке (номер версии не меняется), а в том, что станция **самостоятельно
обновляет хранилище доверенных корней**:

```
/system/vendor/quasar/ca-certificates.crt -> certs/ca-certificates.crt
```

Файл успевает обновиться раньше, чем вы успеваете что-то сделать. Отсюда правило: **окно
доверия ≈ 1–2 минуты после сброса**, и всё надо делать в нём.

Проверить, что именно происходит, можно по логам nginx (если используете свой):

```
SSL_do_handshake() failed (SSL: error:0A000418:SSL routines::tlsv1 alert unknown ca)
```

## 2. Заводская прошивка 0.18.1 не умеет adbd

Заводской образ (`0.18.1.23...20230810.factory`) доверяет CA, но **не активирует ADB** по
конфигу — ключ `system_config.adbd` в нём просто не обрабатывается. Нужна прошивка
`0.369.1.46+`.

Отсюда трюк из `yandex-station-root`: после сброса станции подсовывается **один** апдейт `.46`
через поддельный `update_manifest.json` (ZIP качается с настоящего CDN Яндекса), после чего
активация проходит.

## 3. `.50` отвергает CA-цепочку

Сборка `0.369.1.50...` (и новее) не доверяет eMudhra. Поэтому:
- либо остаётесь на `.46`,
- либо ставите ADB-гард **до** обновления — он переживёт переезд на `.50`.

Гард — это подмена `/system/vendor/quasar/activate_adb.sh` обёрткой, которая игнорирует
`deactivate` и заново поднимает сетевой ADB. Оригинал сохраняется рядом как
`activate_adb.root_original.sh`.

## 4. musl и ядро 4.9: падение по clock_gettime64

Если собрать бинарник статически на musl (Alpine), он **падает** на этой станции:

```
shairport-sync[2540]: syscall 403
unhandled level 3 translation fault (11)
```

`syscall 403` на arm32 — это `clock_gettime64`, появившийся в ядре 5.1. Здесь ядро **4.9**.

`-D_TIME_BITS=32` помогает не всегда (зависит от того, как передаются флаги в подпроекты).

**Решение:** собирать под старый glibc (Debian buster, glibc 2.28). На станции glibc 2.30,
libstdc++ 6.0.28 и libgcc_s есть — бинарник заводится без дополнительных библиотек.

Заодно: статически линкуйте только отсутствующие библиотеки (`libconfig`, `libpopt`), а
`libasound`/`libssl`/`libc` — динамически, они на устройстве есть.

## 5. `mediad` монопольно держит ALSA

Любой приёмник (AirPlay, Spotify Connect) упрётся в:

```
The output device "plughw:0,0" is busy
```

Держит его `/system/vendor/quasar/maind --mediad`. В карте **один субпоток**, dmix не
используется (`/dev/shm` пуст), так что разделить устройство нельзя.

Но: если `mediad` убить, он **перезапускается сам** и устройство больше не захватывает, пока
ему не понадобится. Этого достаточно.

```sh
# /etc/airplay-free.sh
for p in $(ps -o pid,args | grep -F "maind --mediad" | grep -v grep | cut -d" " -f1); do
  kill -9 "$p" 2>/dev/null
done
```

Вызывать: при загрузке (с задержкой ~30 с) и по хукам плеера
(`run_this_before_entering_active_state`).

Цена: пока играет AirPlay/Spotify, Алиса не сможет говорить. Это осознанный размен.

## 6. Обновления отключаются в launch.json

```
/system/vendor/quasar/launch.json
```

Убрать задачу `updatesd` — и OTA больше не запускается. Проверка:

```sh
grep -c updatesd /system/vendor/quasar/launch.json   # 0
```

Учтите: установщик `yandex-station-root` при отключении обновлений пытается перемонтировать
`/` в rw и падает с `mount: ... Device or resource busy`, **уже после** записи файла. Ошибку
можно игнорировать, но проверяйте результат.

## 7. Мелочи, на которые уходит время

- **`/data/local/tmp` не существует** — `mktemp` падает с `No such file or directory`.
  Перед установкой: `adb shell mkdir -p /data/local/tmp`.
- **`/` обычно смонтирован read-only.** Перед записью: `mount -o remount,rw /`.
  Обратно — `mount -o remount,ro /` (не обязательно, при перезагрузке вернётся само).
- **busybox без `nohup`** на OpenWrt: демоны запускать через `start-stop-daemon -S -b -x`.
- **`init 6` не работает** (не PID 1) — перезагружать через `reboot`.
- **DNS-подмену нельзя делать глобальной** на роутере: телефон с приложением «Дом с Алисой»
  ходит на те же домены и получает заглушечный конфиг → «нет списка устройств».
  Подменяйте только для MAC станции, а остальное — через DNAT по её адресу.
- **Станция кеширует IP** и иногда ходит на настоящий адрес Яндекса мимо вашего DNS.
  Надёжнее завернуть её трафик на прокси через `dnat`/`redirect` по MAC.
- **QUIC (UDP 443)** капризен: если перехватываете только TCP, станция может обновиться по
  QUIC незаметно для вас.
